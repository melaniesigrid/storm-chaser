01

What was built

A React Native application for storm-chasing hobbyist meteorologists, built with Expo SDK 57, Expo Router and TypeScript in strict mode. It fetches live weather for the device's position, scores how interesting the atmosphere actually is, and turns a photograph into a timestamped, geotagged, weather-stamped field report held on the device.

All four required feature areas are complete, along with every one of the seven listed bonus features.

02

Running the project

No API keys and no accounts. Open-Meteo is keyless, and cloud sync stays off unless it is pointed somewhere. Node 20 or newer. 

git clone https://github.com/melaniesigrid/storm-chaser.git
cd storm-chaser
npm install
npx expo start

Then press i for iOS, a for Android, or scan the QR code with Expo Go. Camera, location and maps need a real device or a development build; for a native build with the full map provider, run npm run ios or npm run android.

The web build is also live at stormchaser-field.vercel.app/app — the real app, minus the native camera and map.

05

Architecture and decisions

  • Feature slices over layer folders. src/features/<domain>/ each own their model/, data/, hooks/ and components/. model/ is the bottom layer and contains no React and no I/O, which is why the interesting logic is testable without a renderer or a device.
  • A Result<T, AppError> at every boundary. Data access and network code return a result rather than throwing, so callers are forced to handle the failure branch and the UI always has something concrete to render. Error kinds map onto specific UI responses rather than a single generic error state.
  • A repository behind an injected store port. StormRepository takes a KeyValueStore interface rather than calling AsyncStorage directly, so the whole data layer is testable with an in-memory store and no native modules. Its clock and id generator are injected for the same reason.
  • The weather snapshot is denormalised onto each report. A field log entry has to stay readable years later without re-querying a forecast API that no longer holds historical data for that timestamp, so the conditions at capture are copied onto the record rather than referenced.
  • Photo first, record second. If the image cannot be copied into permanent storage the mutation stops before a report is written, so the log can never point at a file that is not there. Deletion runs the other way round: the record goes first, because an orphaned file is recoverable and a record pointing at nothing is not.
  • A theme is data. Colour, typography, motion, brand and atmosphere are all tokens on a theme object. Components never test a theme by name; a theme opts into a behaviour by defining the token for it. This document is drawn in one of them.
06

Testing

734 unit tests across 33 suites, run under TypeScript strict mode. They target logic rather than pixels: formatting, the severity model, API mapping, the repository and its migrations, the theme and typography contracts, WCAG contrast, icon mapping, the community layer, storm legends and EXIF date resolution.

The suite runs in two timezones, the default UTC and, via npm run test:tz, America/Toronto, because a whole class of date bug in this app is invisible under UTC. 

npm test          # 734 tests
npm run test:tz   # the same suite at a negative UTC offset
npm run typecheck # tsc --noEmit, clean
npm run lint      # eslint, clean
